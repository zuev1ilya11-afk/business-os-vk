# Правило общения при работе с сервером

Пользователь работает через серверную консоль, в которую длинные команды и
блоки текста не вставляются. Это постоянное правило для следующих задач
Business OS, включая диагностику, установку и восстановление.

- Команды, которые пользователь должен вводить на сервере, ограничивать
  60 символами в каждой строке. Перед отправкой проверять длину.
- Каждую команду показывать в отдельном блоке для копирования; давать только
  ближайший необходимый шаг, без большого списка команд на будущее.
- Не предлагать вставку многострочных скриптов, heredoc, длинных `python -c`,
  base64, длинных URL или команд с продолжением строки через обратный слеш.
- Длинные пути сокращать переходом в каталог или короткими переменными,
  задавая их короткими самостоятельными командами. Не полагаться на переменные
  из прошлых запусков без подтверждения, что они заданы в текущей консоли.
- Сложную диагностику и установку заранее готовить в проверенном файле
  скрипта/пакета; пользователю давать короткие команды скачивания и запуска.
  Не использовать сокращение команды как повод убрать проверки безопасности.
- Запускать скачанный установщик только после успешного скачивания.
  Не предлагать `curl | sh`, `curl | python` или аналогичные конструкции.
- Диагностический вывод ограничивать объёмом, который помещается на скриншоте;
  полный журнал сохранять отдельно, без публикации секретов и клиентских данных.

Правило добавлено по прямой просьбе пользователя 31.10.2026. Оно относится к
командам для ручного ввода пользователем, а не к внутренним вызовам инструментов.
