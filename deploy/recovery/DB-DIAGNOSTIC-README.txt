Business OS: проверка сохранённых журналов базы и служб

1. Закройте окно предыдущего запуска приложения.
2. Распакуйте все файлы этого дополнения в существующую папку E:\BOS-App.
   Там уже должны быть restore-report.json, отчёт неудачного запуска BOS-App-*.json
   и python-3.12.10-embed-amd64.zip из предыдущего пакета.
3. Дождитесь готовности Docker Desktop и дважды нажмите check-services.cmd.
4. Пришлите созданный рядом файл BOS-Services-Diagnostic-*.json.
   Если последний сбой был на этапе DATABASE, файл называется BOS-DB-Diagnostic-*.json.
   Прежний check-db.cmd также запускает эту же проверку.

Дополнение читает только сохранённые служебные журналы последнего неудачного
запуска, связанного с проверенной резервной копией. Он проверяет журналы базы
и служб приложения, включая службу входа auth. Для чтения используется
временный контейнер без сети с томом неудачного запуска только для чтения.
Контейнер PostgreSQL не запускается. Импорт базы, создание новой копии тома,
скачивание образов и изменение резервной копии не выполняются.
Исходный проверенный том восстановления не подключается.

В JSON попадают только ограниченные диагностические категории и разрешённые
технические признаки. Исходные журналы, SQL, пароли и данные клиентов в него
не копируются. Отчёт сохраняется рядом с check-services.cmd на выбранном диске.

Это сбор причины сбоя, а не исправление или подтверждение готовности приложения.
Не удаляйте сохранённые тома и резервную копию до завершения проверки.
