BUSINESS OS — ПРОДОЛЖЕНИЕ ПРОВЕРКИ, ВЕРСИЯ 2

1. Распакуйте четыре файла в E:\BOS-App с заменой прежних файлов проверки.
   Сохраните рядом ранее полученный BOS-Flow-Check-....json.
2. Оставьте открытым уже работающее приложение и окно start-app.cmd.
   Перезапускать копию и повторно скачивать большой backup не требуется.
3. Запустите check-flow.cmd. Введите логин и пароль владельца, с которыми
   получилось войти. Пароль не отображается. Никому его не отправляйте.
4. Дождитесь результата. Пришлите файл BOS-Flow-Check-....json, который
   появится рядом. Если JSON не появился — снимок окна без введённого логина.

Проверка выполняется через настоящее API запущенной восстановленной копии.
До каждого запроса проверяются локальный Docker, собственный том, все шесть
контейнеров, отсутствие внешней сети и проброшенных портов. При несоответствии
проверка останавливается. Контейнеры, код приложения и миграции не заменяются.

Исправлена ошибка предыдущего скрипта FLOW_STORAGE_URL_INVALID после загрузки
акта: адрес подписанной ссылки нужно проверять по public из локальной
конфигурации gateway, а не только по внутреннему адресу API. Внешний адрес
используется исключительно как часть подписанной ссылки. Сам файл читается
через локальный portal; внешний сервер не вызывается.

Пакет продолжает последний остановленный на UPLOAD_ACT_1 запуск. Проверяются
тот же run_id, manifest, build, имена и роли тестовых сотрудников, метка, сумма,
назначение и состояние заявки. Новые сотрудники и заявка не создаются.
Уже загруженный контрольный акт загрузится повторно; старый файл не удаляется.
Если копия или записи изменились, пакет остановится без автоматического
перехода к созданию новых данных. Действующие клиентские заявки не изменяются. Владелец входит обычным способом, остальные роли включаются
существующим переключателем тестовой копии. Новым сотрудникам пароли не задаются.

Проверяются создание и повтор создания, назначение, запись тестового контакта
(реальный звонок не выполняется), дата/время, выезд и начало работы, загрузка
контрольного PNG как акта и фото, чтение их байтов из Storage, отправка отчёта,
повтор отправки, состояние после обновления данных, запрет проверки мастером,
возврат менеджером и новая отправка. Далее проверяются доступ к финансовому
экспорту, скачивание и целостность XLSX по единственной тестовой заявке.

Google Диск отключён изоляцией. Проверка подтверждает этот запрет, оставляет
отчёт «На проверке» и заканчивается PARTIAL_EXTERNAL_ARCHIVE_DISABLED.
Она НЕ подделывает архив и НЕ отмечает заявку выполненной. Принятие отчёта,
окончательные начисления, рекламации, гонки менеджеров, поздние события
интеграций, история прежних ревизий и экран телефона остаются непроверенными.
Расчёт 552,50 + 100 рублей проверяется как сумма ожидающего отчёта, не как
подтверждённая выплата. Проверяется текущая восстановленная версия приложения,
а не ещё не установленная ветка stage-0.

При первом отказе проверка прекращается и сохраняет частичный отчёт. Не
запускайте её многократно без разбора результата: для следующей остановки
потребуется проверить состояние и точку продолжения. Они сохраняются в этой копии для осмотра через
интерфейс; скрипт ничего не удаляет. Основной backup и production не меняются.

JSON содержит только этапы, HTTP-коды, время ответа, ID синтетических записей,
их состояния и контрольные суммы. Пароль, сессии, подписи ссылок, данные
реальных клиентов, имена действующих сотрудников и сырые ошибки не сохраняются.
Сам XLSX не сохраняется и не отправляется наружу. Python используется из
уже распакованного BOS-App; подключения к интернету не требуется.
