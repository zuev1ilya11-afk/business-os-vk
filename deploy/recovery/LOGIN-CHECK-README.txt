BUSINESS OS — ПРОВЕРКА ВХОДА В УЖЕ ЗАПУЩЕННУЮ ЛОКАЛЬНУЮ КОПИЮ

1. Распакуйте содержимое этого архива в E:\BOS-App, рядом с start-app.cmd.
   Пакет использует Python, уже включённый в BOS-App. Скачивать его не нужно.
2. Оставьте открытым окно, в котором запущен start-app.cmd.
   Если окно закрыто, сначала запустите start-app.cmd и дождитесь открытия
   приложения. Повторный запуск приложения создаёт новую тестовую копию.
3. Запустите check-login.cmd. Обычно проверка занимает до двух минут.
4. Пришлите появившийся рядом файл BOS-Login-Diagnostic-....json.
   Если файл не появился, пришлите снимок окна check-login.cmd.

Это диагностика, а не исправление. Перезапускать работающую копию для её
запуска не требуется. Проверка не удаляет и не останавливает контейнеры,
не меняет учётные записи и не обращается к рабочему серверу.

Проверка обращается к локальному API с одним случайным несуществующим логином
и случайным паролем. Это проверяет путь до проверки учётных данных, а также
может добавить запись счётчика попыток входа в тестовую базу. Ваши логин
и пароль не запрашиваются. Настоящий успешный вход и последующая загрузка
данных аккаунта этой диагностикой не подтверждаются.

Отчёт содержит метод и локальный адрес каждого диагностического запроса,
время его начала (UTC), время ответа, первый неуспешный запрос проверки,
коды ошибок, признаки доступности служб и
обезличенные категории сообщений. Пароли, токены, имена сотрудников,
данные заявок, полная конфигурация и исходные журналы в отчёт не включаются.
Это запросы самой диагностики, а не история неудачной попытки в браузере.
Журналы за последние 30 минут приведены отдельно; точное совпадение записи
журнала с запросом автоматически не утверждается.
