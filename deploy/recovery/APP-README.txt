BUSINESS OS — ЛОКАЛЬНАЯ ПРОВЕРКА ПРИЛОЖЕНИЯ

Версия 2 от 15.11.2026. Исправлена совместимость с тремя подтверждёнными
вариантами путей функций и локальными deno.json в резервной копии.
Если версия 1 уже распакована в E:\BOS-App, закройте её окно запуска
и распакуйте этот архив в ту же папку с заменой файлов пакета.

Пакет продолжает успешное восстановление из BOS-Restore. Использует
сохранённый том и создаёт отдельную рабочую копию без повторного импорта БД.

ЗАПУСК

1. Сохраните ZIP на E: и распакуйте, например, в E:\BOS-App.
   Папка запуска должна находиться вне BOS-Backup.
2. Откройте Docker Desktop и дождитесь готовности Linux Engine.
3. Дважды щёлкните start-app.cmd. Администраторские права не нужны.
4. Дождитесь отдельного окна Edge. Войдите обычным логином и паролем
   Business OS. Вход через VK и отправка сообщений отключены.
5. Оставьте окно запуска открытым. Для остановки нажмите в нём Ctrl+C.

Python включён в архив. Его файлы, профиль отдельного браузера и отчёты
создаются рядом с start-app.cmd, то есть на E: при такой распаковке.
Скачивания из отдельного окна Edge сохраняются в подпапку Downloads.
Пакет не переносит виртуальный диск Docker. Его расположение зависит
от настройки Docker Desktop. Проверка свободного места внутри Docker
не доказывает наличие места на физическом диске Windows.
При APP_SYSTEM_DISK_SPACE_LOW освободите место на системном диске:
пакет требует минимум 1 ГиБ. Автоматически ваши файлы не удаляются.

Исходный BOS-Backup ищется на E:, рядом с папкой запуска и в профиле
пользователя. Принимается только комплект из приложенного restore-report.json.
Папку C:\Users\777\BOS-Backup можно оставить на месте: она читается без
записи. Повторно скачивать архив с сервера не нужно.

АВТОМАТИЧЕСКАЯ ПРОВЕРКА

— совпадение комплекта с успешным отчётом;
— локальный Docker, метка исходного тома и отсутствие его использования;
— точные сохранённые образы и байты файлов;
— база на отдельной копии, количества записей и guard отчётов;
— REST, Auth, Storage, Edge и локальная раздача приложения;
— связь записей Storage с файлами и фактическая выдача их байтов.

Службы используют свежие локальные ключи, не имеют внешней сети и
опубликованных Docker-портов. Отдельный профиль Edge блокирует внешние
соединения. Рабочий сервер не меняется.

ЧТО ПРОВЕРИТЬ В ОТКРЫВШЕЙСЯ КОПИИ

— вход, список заявок и состояние после обновления страницы;
— фото и акт в существующем отчёте;
— отправку отчёта мастером и принятие руководителем на тестовой заявке;
— начисления в финансах и скачивание детализации Excel.

Изменения относятся только к новой рабочей копии. Внешние push, Avito,
Hands и Google-интеграции в этой проверке недоступны.

ОСТАНОВКА И ОТЧЁТ

После Ctrl+C удаляются только контейнеры текущего запуска. Исходный том,
архив и рабочий том сохраняются. Повторный запуск создаёт ещё одну копию
из исходного тома, а не продолжает предыдущую рабочую сессию.
Не очищайте все Docker volumes: там находится проверенная БД.

При STOPPED рядом с пакетом создаётся BOS-App-*.json, если ошибка
произошла после подготовки каталога отчёта. Для разбора подходит этот JSON
или короткий вывод окна. Не отправляйте private-config.json, database.dump,
globals.sql и закрытые журналы: они содержат секреты и рабочие данные.
Для отдельной проверки структуры есть check-app.cmd. Он не запускает
Docker; созданный им BOS-App-Diagnostic-*.json также подходит для разбора.

Успешный локальный запуск ещё не означает полной готовности аварийного
восстановления. Согласованность общего снимка БД/Storage, исходные расширенные
атрибуты и сквозные действия пользователя проверяются отдельно.
disaster_recovery_ready остаётся false.
