# PR296 — установка формы заявки на действующий RU-сервер

Публикация и установка разрешены пользователем 20.10.2026. PR296 объединён
в main как `27dccf2e61b64c44bfa96b97552425f04db97848`; исходный commit
`6b966c38fbd795612299dc2e793d10c452d7d6fe` прошёл CI run `39434289316`.

Скриншот диагностики сервера от 20.10.2026 подтвердил:

- Build `77899953454eb1870e2e`, manifest SHA-256
  `8218da5e8f6381938aef13331953b11507d43a7ecad683fb051126ff5f883a49`.
- Полную целостность файлов frontend и точное совпадение mini-app-api с baseline.
- Три зависимости API совпадают с `DEPENDENCIES` в `package/backend.py`.

Целевая RU-сборка: `f2c8c8ee697f23936ec2`.

```sh
python3 /root/bos296.pyz --check
python3 /root/bos296.pyz --apply
```

`--check` проверяет текущие web/API, схему PostgreSQL 17, контейнеры и ресурсы.
Не выполняет DDL, замены файлов или перезапуски.

`--apply` сначала копирует backend и исходный кеш компилятора в отдельный
каталог. В текущем образе edge-runtime, без сети, воспроизводит существующий
bundle байт в байт. Только после совпадения собирает новую версию с теми же
зависимостями. Тестовый gateway получает фиктивные ключи, работает без внешней
сети и проходит health/auth/CORS-проверки. Существующие секреты не выводятся.

До миграции создаются полные копии frontend/API и приватный `pg_dump` базы.
Архив проверяется через `pg_restore --list`, затем целиком читается и
распаковывается командой `pg_restore --file=/dev/null` без подключения к БД.
Это проверка архива, а не пробное восстановление базы.

Миграция выполняется одной транзакцией с повторной проверкой схемы,
`lock_timeout=5s`, `statement_timeout=60s`, транзакционной блокировкой и
уведомлением PostgREST о новой схеме. Старые строки не переписываются.
Частичная или неизвестная схема останавливает установку.

API заменяется внутри текущего release; перезапускается существующий edge.
Frontend переключается атомарно, затем перезапускается существующий Caddy.
Проверяются HTTPS-хеши и API. RU-маршрутизация, конфигурация, остальные API,
интеграции и зависимости не заменяются. Все 36 изменённых модулей frontend
сверены с базовой RU-сборкой. Generic build не используется как полный web-каталог.

Ожидаемый конец успешной установки:

```text
RELEASE_OK BUILD_ID=f2c8c8ee697f23936ec2
```

Откат:

```sh
python3 /root/bos296.pyz --rollback
```

Откат возвращает код после проверки отсутствия посторонних изменений.
Добавленная схема и все введённые заявки сохраняются. Недоступность БД не
блокирует независимое восстановление файлов: неопределённый статус БД
выводится после восстановления кода. Полный dump автоматически поверх
текущих данных не восстанавливается. Незавершённые попытки сохраняются
в каталогах `intake-296-*-history-*`; активная/прерванная активация требует отката.

Локальная проверка: 44 сценария установки/сбоев/отката/резервного копирования,
4 транзакционных сценария на одноразовом PGlite PostgreSQL 18.6. Docker и HTTPS
в файловых тестах заменены явными тестовыми границами. Настоящая компиляция,
PG17 schema comparison, проверка архива базы и HTTPS — обязательные проверки
на сервере до сообщения `RELEASE_OK`. UI/SQL/API основной функции прошли
отдельный CI выше; установку production это не подтверждает.
