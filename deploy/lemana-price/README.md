# Прайс «Лемана Про» от 11.11.2026

Источник: «12 Карнизы и светозащита_11.11..26.xlsx», Sheet1, A1:C68.
SHA-256 исходного документа: a63de7adb26dbee73af829d665d6df4fdbc580ed7909f4c02ec8f3c7aa5cbbaf.
40 строк с ценами: 39 услуг и условие минимального выезда 2800 ₽.
Цены включают НДС. Названия, единицы, состав и условия сохранены в
`data/lemana-price-2026-11-11.json` с диапазоном ячеек каждой позиции.
Единица шторы плиссе взята из B35 внутри строки услуги A34:C35.
Незаполненный предел «до ХХ км» сохранён и обозначен в интерфейсе.

Прайс доступен отдельной вкладкой в памятках мастера. При выборе источника
«Лемана Про» новые позиции в заявке получают этот прайс. Сохранённые строки,
количества, ручные цены и итог заявки автоматически не изменяются.
Минимальный выезд не прибавляется отдельной услугой и не доступен как вычет.
Общая сумма меняется только явно: вручную или кнопкой суммы позиций.
Невыполненные работы проверяются сервером по версии прайса. Финансовая
группировка использует сохранённый service_id для новых структурированных
строк; старое сопоставление названий и сохранённые выплаты сохраняются.

## Установка поверх действующей российской версии

Сначала требуется завершить предыдущее исправление отчётов. Проверяются
точные контрольные суммы исправленных report-api и order-lifecycle-api.
Не заменять production всей веткой и не выполнять npm build в live-каталоге.

В отдельном checkout этой ветки выполнить по одному шагу:

```sh
python3 deploy/lemana-price/release.py stage
```

После STAGE_READY=true:

```sh
python3 deploy/lemana-price/release.py apply
```

Откат только этого обновления:

```sh
python3 deploy/lemana-price/release.py rollback
```

Stage читает live-файлы, сохраняет копии в /root/bos-lemana-price, обновляет
восемь модулей в копиях frontend, два модуля каталогов в двух API и закрытую
копию финансовой модели в mini-app-api. Действующие endpoint mapping сохраняются.
Расположение каждого web-модуля берётся из проверенного build-version.js:
модули стартовых пакетов обновляются внутри пакета, finance-data.js — отдельным
файлом, если так указано в manifest. Отсутствие модуля в manifest блокирует
подготовку. Проверяется также установка и откат этой смешанной структуры.
Для employee-profile-patch.js проверяется и меняется только целый блок
вкладок прайса: существующий код финансов и остальные байты сохраняются.
Это учитывает отличающуюся действующую реализацию профиля сотрудников.
Изменения внутри блока вкладок, его отсутствие или дублирование останавливают
подготовку. Для остальных модулей любые другие различия исходников также
останавливают подготовку.
Три старых ESZIP сначала воспроизводятся с точными зависимостями. Затем сеть
builder отключается, собираются новые пакеты и проверяется список изменившихся
модулей. Изолированный runtime проверяет загрузку, роли, отправку/повтор/приёмку,
новую цену и версию, запрет подмены цены/вычета минимального выезда и авторизацию
финансового API на синтетических сервисах. Реальные заказы не используются.

Apply сверяет снимки и публичные файлы, устанавливает проверенные файлы,
перезапускает только Edge, проверяет здоровье и публичные контрольные суммы.
При ошибке восстанавливает копии; неизвестное параллельное изменение блокирует
откат. SQL, исторические заявки, ставки выплат и интеграционные настройки не меняются.
После применения необходима проверка в рабочем приложении: вкладка прайса,
новая заявка Лемана Про, сохранение количества/цены и отправка отчёта.

## Проверки

```sh
node scripts/build-lemana-price.cjs --check
node --test tests/lemana-price.test.cjs
python3 -m unittest discover -s deploy/lemana-price
```

Браузерные сценарии: tests/lemana-price.spec.js. GitHub workflow
«Lemana price checks» запускает их в сетевой изоляции вместе с регрессиями
ввода заявок, старого прайса и финансов. Сам workflow ничего не публикует на сервер.
