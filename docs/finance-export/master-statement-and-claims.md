# Рекламация № 7395762: диагностика, исправление ещё не установлено

Сообщение пользователя: первоначальная заявка была закрыта и оплачена;
повторный бесплатный выезд не должен начислять первоначальную зарплату ещё раз.

Причина воспроизведена на синтетических данных через настоящий claims-api и
finance-data: первоначальное начисление 600 ₽ относится к сентябрю, после
reopenClaim/closeClaim переносится в октябрь. В `reopenClaim` completed_at
сбрасывается, в `closeClaim` записывается время закрытия претензии. Дополнительно
сохранённая в репозитории guard_order_completion сбрасывает completed_at и
report_reviewed_at при начале нового цикла. Сумма master_payout остаётся прежней.

Следовательно, простое исключение всех is_claim из зарплаты удалило бы также
законную первоначальную зарплату. Обнуление master_payout по номеру заявки
здесь не выполнено. Формулы зарплаты и production-БД пока не изменены.

Перед выбором способа исправления требуется текущая строка № 7395762,
даты её претензий и доступные колонки истории. Скрипт
`deploy/finance-export/check-claim.py` предназначен для этой проверки:
привязывается к подтверждённому Edge-контейнеру, разрешает фактический маршрут
REST → DB, выполняет только транзакцию READ ONLY. Выводит даты, начисление,
оплату повторного выезда и названия полей истории. Не выводит контакты,
вложения, секреты, SQL или адреса сервисов; не перезапускает контейнеры.

Следующий шаг — восстановить первоначальное начисление из подтверждённой
истории и сохранять его при открытии рекламации; бесплатное закрытие претензии
не должно создавать новое начисление. Дата или сумма первоначальной работы
не должны восстанавливаться предположением по дате повторного визита.

Пакет `bos-finance.pyz` относится к предыдущему установленному релизу и не
обновлён этой веткой. Его повторный запуск не публикует новую кнопку. Публикация
нового кода требует отдельного пакета относительно текущего production BUILD
`76372a6dd138d4168acd`, после серверной проверки рекламации.
