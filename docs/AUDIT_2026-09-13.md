## D. Что изменено в production

Только `gas-bridge-health` v4 → v5: диагностический запрос снова использует ту же derivation подписи, что и рабочий архиватор. Live тест вернул `ACT_REQUIRED`, то есть подпись принята и запрос остановлен до записи файлов.

Остальные исправления — **в ветке/PR**, не развёрнуты в Netlify, Supabase или GAS. Merge GitHub Pages сам по себе не развёртывает SQL/Edge/GAS. Production заказы, сотрудники и выплаты не переписывались; DB-проверки credentials и grants выполнены в откатываемых транзакциях.

## F. Тесты

Добавлены `tests/server-audit.test.cjs`, `tests/gateway-audit.test.cjs`, `tests/full-stack-audit.spec.js` и helpers. Сетевые тесты приведены к актуальной простой схеме авторизации и расширены. Тесты нового main сохранены, кроме ожидаемых версий изменённых assets. Live health assertions не ослаблены. Fixture теста retry сохраняет созданный заказ для последующего bootstrap, вместо противоречивого постоянного пустого списка; проверка одного request_id сохранена.

Серверный набор: 24 теста. Playwright: 48 тестов. CI запускает оба полностью через `npm ci`, Node24, Chromium. `testMatch` исключает случайный повторный запуск node:test при обнаружении Playwright. Lockfile добавлен.

Модель SQL специально ограничивает default select 1000 записями, поддерживает `.range`, uniqueness для order request_id и выполняет реальный код обработчиков. Она **не доказательство** корректной транзакционности PostgreSQL. Для RPC credentials отдельно проверена реальная БД с bcrypt: корректный пароль, неверный пароль, отключение, восстановление; всё ROLLBACK.

## H. Известные риски и непроверенные границы

1. **HIGH: registerByPhone. Подтверждено.** Валидный VK пользователь, знающий телефон непривязанной карточки manager, может привязать её и получить роль. Локальный вызов реального handler вернул linked=true/manager без доказательства владения номером. Signed launch доказывает VK identity, не право на карточку. Не отключено, чтобы не сломать onboarding без продуктового выбора. Рекомендуется owner invite: одноразовый случайный код, hash в БД, короткий срок, связь с immutable staff ID, атомарное погашение; альтернативно предварительная привязка VK ID владельцем. OTP — отдельная интеграция/стоимость. Нужен выбор процесса.
2. **HIGH: archive status view пока открыт в production.** Миграция готова, проверена откатываемой транзакцией; требуется deployment. Она сохраняет доступ backend service_role.
3. В существующих 13 заказах агрегатная DB-проверка выявила 1 расхождение master payout с формулой, 0 отрицательных, 0 расхождений manager/dispatcher. Нельзя определить намеренность ручной корректировки по одному числу; запись не изменялась. Нужна сверка с владельцем.
4. Исправления session syntax охватывают изменённые handlers; это не формальная верификация всех старых/интеграционных endpoints. Действующие debug/once endpoints `test-pin-session`, `e2e-create-staff-order-once`, `archive-order-2-once` и deprecated `business-os-api` просмотрены: возвращают410, не исполняют старые операции.
5. Некоторые вспомогательные загрузки/архивирование/файловые цепочки ещё используют самостоятельный fetch. Все возможные таймауты и частичные записи нескольких backend операций не покрыты. Полный сценарий отчёт → файлы → Drive → закрытие на реальных данных требует отдельной проверки.
6. Пагинация устраняет усечение, но увеличивает объём bootstrap. Проверено1205, не нагрузка десятков тысяч. 66 скриптов остаются: масштабный refactor не проводился.
7. DB advisors: mutable search_path у trigger-функций и прочие предупреждения не объявлены исправленными. Credential SECURITY DEFINER RPC не доступны anon/authenticated; фиксированный search_path проверен.
8. Нет полного ручного покрытия всех filters/settings/cities, cancel/reassign во всех ролях, длинных списков и всех мобильных модалок. Повторная финализация отчёта и финансовые ручные правки требуют расширенного сценария; тест комментария не гарантирует сохранность при любом финансовом изменении.
