## Архитектура

`apps/public-site` — самостоятельное React/TypeScript + Next.js приложение со своей сборкой и lockfile. Репозиторий не переводится в монорепозиторий. Сайт получает только публичные DTO общего API. Существующая модель orders, сессии, согласия, сообщения, вложения и расчёт work-items сохраняются. Дополнительные маршруты backend включаются явным `websiteEnabled`.

Для staging сайт, `/client/` и `/client-api/` работают на одном origin: cookie host-only, токены не передаются в URL. Отдельный поддомен кабинета предусмотрен конфигурацией, но без внедрения и проверки SSO он потребует отдельного входа. Безопасный выпуск первой версии — кабинет на `/client/` через reverse proxy, технический origin сотрудников отдельно. Новый клиентский кабинет не создаётся.

Публичный каталог — метаданные поверх client_catalog, связанные с `service-catalog.js`. Числовая цена разрешена только при подтверждённом fingerprint исходной позиции; изменение исходного прайса сбрасывает показ цены в «после уточнения», до повторного подтверждения руководителем. Исторические сметы не переписываются. Длина становится количеством для погонных метров; неизвестные коэффициенты высоты/материала/выезда помечают расчёт требующим согласования. Новых коммерческих коэффициентов нет.

Юридические страницы читают документы PR #303 без изменения текста и версий. Неутверждённые документы и реальные реквизиты блокируют публичный выпуск. Отзывы показываются только после завершённой заявки и отдельной модерации, без вымышленных оценок.

## Порядок реализации

1. Добавочная схема, связь прайса, API сайта и B2B, rollback.
2. SSR-страницы, дизайн, каталог, поиск, SEO и контент.
3. Пошаговая форма, существующий OTP, файлы, переход в PWA.
4. Очередь лидов сотрудников, проверка общего жизненного цикла.
5. Контрактные, интеграционные, права, восстановление, сборка и браузерная проверка.
6. Отчёт с фактическими результатами и оставшимися блокерами. Production, DNS и secrets не меняются.
