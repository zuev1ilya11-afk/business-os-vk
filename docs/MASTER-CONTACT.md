# Подтверждение связи с клиентом

Кнопка «Связался с клиентом» использует существующий `master-workflow-api/markCalled`. Открытие заявки, `tel:` и возвращение в приложение ничего не подтверждают. Форма договорённости больше не вызывает `markCalled` автоматически при сохранении: связь подтверждается отдельной кнопкой.

Новый явный запрос передаёт `contact_confirmed: true`. Старые кешированные клиенты без этого признака сохраняют прежнюю отметку звонка без нового авторства; это не считается доказанным успешным контактом. Сервер проверяет подписанную сессию, актуального активного сотрудника с ролью master и назначение заявки. Управленческие роли и просмотр кабинета мастера права записи не получают.

`master_called_at` остаётся единственным временем события. Новые `master_called_by_staff_id` и `master_called_by_name` сохраняют автора и снимок имени. Миграция не заполняет эти поля для старых строк. Только полный набор полей отображается как «Связался · DD.MM, HH:mm»; старое время без авторства — «Звонок отмечен», одна договорённость — «Связь не подтверждена». Общий `BOS_CONTACT_STATUS.html(order,{details:false})` использует Europe/Moscow; `details:true` добавляет имя первого автора, а не текущего назначенного мастера.

Оптимистическая блокировка UPDATE включает назначение и поля подтверждения. Повторные конкурентные запросы возвращают первый сохранённый результат. Триггер `zz_bos_guard_master_contact` работает SECURITY INVOKER: первичное авторство допускается только при PostgreSQL `current_user = service_role`, совпадении автора с текущим назначенным активным мастером и активной заявке. Время берётся из часов БД, имя — из `business_staff`; клиентские значения не являются источником истины. Политики RLS и grants таблиц не меняются.

После первого подтверждения триггер сохраняет все три поля при любых обновлениях, включая смену мастера, изменение имени/удаление сотрудника, повторную синхронизацию Hands и существующий сброс рабочего цикла. UUID автора намеренно не имеет внешнего ключа. Триггер идёт после существующих BEFORE-триггеров; их правила отчётов, этапов и выплат не меняются. Обработчик Hands и ручные исключения квартиры/комментария не изменены.

Миграция должна быть применена до обновления Edge Function. SQL-контракт в `scripts/test-master-contact.sh` запускается существующим `scripts/test-order-guards.sh` только на явно заданной одноразовой PostgreSQL; фикстуры откатываются. Он проверяет повторное применение миграции, запрет authenticated/insert/чужого/неактивного автора, серверные часы/имя и сохранение при переоткрытии/отклонении отчёта/переназначении. Supabase CLI недоступен в рабочей среде; файл миграции создан по существующему формату проекта. Проверка SQL выполняется обязательным CI PostgreSQL перед merge.
