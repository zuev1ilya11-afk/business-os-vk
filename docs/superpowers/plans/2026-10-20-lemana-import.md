# Лемана Про, количество работ и импорт — план

> Исполнение: superpowers:executing-plans. ТЗ пользователя от 20.10.2026 — обязательный контракт.

**Цель:** отдельный источник с общей схемой начислений Hands, позиции работ и подтверждаемый импорт только новых заявок.

**База:** main 27dccf2e61b64c44bfa96b97552425f04db97848. Чистый отдельный clone; найденные старые worktree имеют недоступный git-dir и оставлены без изменений. Серверные тесты до изменения: 770/770.

**Ограничения:** без production-доступа, без загрузки образца в БД, без реальных клиентских фикстур, без изменения истории, без отключения Hands. Существующая БД обслуживает одну компанию: tenant/company/organization колонок в миграциях нет. Не вводить фиктивную многокомпанейность.

**Архитектура:** сохранить source и integration identity отдельно. Canonical label в существующей общей payroll-библиотеке, отдельный predicate расчётной группы. work_items — nullable JSON снимок основных позиций; ранее структурирована только uncompleted_work_items (другая сущность), а основные работы были текстом work. Строковые legacy работы не разбирать в тарифы. Общая сумма меняется только по явному действию пользователя. Импорт через mini-app-api: XLSX → серверный разбор/проверка → подписанный предпросмотр → выбранные строки → серверная повторная проверка → атомарный SQL RPC. Ни upsert, ни update существующих заказов.

## Проверяемые риски
- Повторное подтверждение и гонка с ручным созданием: единая блокировка номера + constraint/trigger на вставке.
- Исторические суммы и отчётные снимки: отсутствие backfill, нет повторного умножения стоимости.
- Excel: ведущие нули, числовые и текстовые даты, переставленные заголовки, формулы, ZIP limits.
- Подмена preview/выбранных строк/мастера: HMAC, срок, actor, серверный RBAC и повторная валидация.
- UI: 360px, редактирование после открытия, источник Hands объединяется только визуально.
