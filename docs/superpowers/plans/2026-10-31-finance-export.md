# Финансовая детализация: план реализации

**Цель:** серверная выгрузка XLSX по текущему периоду и фильтрам раздела «Финансы», без изменения формул и production.
**Основание:** подробное ТЗ пользователя от 31.10.2026. Работа разрешена в отдельной ветке; merge/deploy запрещены.
**База:** main `80a97b374357706a5e1a1ca4f16d9bfdaaf773aa`, чистая отдельная копия, ветка `feat/finance-detail-xlsx-20261031`.

## Решения

- Использовать существующие `finance-data.js`, `finance-expenses.js`, `order-payroll.js`, `salary-periods.js` на сервере. Не пересчитывать исторические начисления.
- Авторизация через существующую подписанную X-BOS-Session и активную запись business_staff; только owner/manager. Тело запроса не определяет права.
- Два read-only действия mini-app-api: предварительный просмотр и получение файла. Отпечаток данных защищает от скачивания изменившейся после просмотра выборки.
- Сервер читает только явный набор текстовых/числовых полей, с пагинацией. XLSX создаётся на сервере потоковым OOXML/ZIP; браузер только скачивает готовый Blob. Без зависимостей, новых таблиц и временных публичных файлов.
- Листы: Сводка, Заявки, Работы, Мастера, Источники; Расходы при наличии расходных записей. Исторические отсутствующие значения остаются пустыми. Даты/числа типизированы, текст не исполняется как Excel-формула.
- Действующие фильтры: период, мастер, город, источник, работа. Поиск мастера и открытая карточка мастера учитываются как дополнительное сужение выборки с отображением в предпросмотре. Фильтра статуса в текущем разделе нет; новый фильтр не добавляется.
- При изменении данных между экраном и предпросмотром предложить обновить экран, не скачивать несогласованные суммы.

## Зафиксированные ограничения существующей логики

- Главная панель владельца считает основные работы без допработ; «Финансы» включает допработы. Экспорт следует «Финансам».
- Работы в текущих финансовых фильтрах сопоставляются с каталогом по строке work, а не work_items. Фильтрация сохраняется, лист работ использует сохранённые work_items, когда они есть.
- Отдельных полей скидки, произвольной корректировки и оплаты в используемом контракте нет: пусто, не ноль и не догадка.
- Доступа к production-данным в этой сессии пока нет. Реальную сверку нельзя выдавать за проверку синтетических фикстур.
