# Новая заявка — реализация и проверка

База работы: актуальный `origin/main` (`3fb9bd0`), отдельный worktree и ветка `feat/new-order-intake-20261020`. Существующие рабочие каталоги не изменялись. Merge, применение миграции и обновление production не выполнялись.

## Что изменилось

Форма сохраняет тёмную тему и реальные компоненты приложения. Пять разделов: основная информация, клиент, адрес, работы, дополнительно. На компьютере используются две колонки, на телефоне — одна. Планирование, условия, стоимость, мастер и комментарий остаются доступными. Источник теперь выбирается из списка с прежними значениями.

Номер необязателен; сохраняются буквы, разделители и ведущие нули. При пустом поле остаётся прежний автоматический номер. Ручной номер показывается и ищется в существующих списках, карточках, расписаниях, финансовых и отчётных представлениях. Изменения этих экранов ограничены чтением новых полей: их структура не переделывалась.

Дата вводится как ДД.ММ.ГГГГ или выбирается в календаре. По умолчанию берётся календарная дата Москвы. Есть native fallback для браузеров/VK iframe, запрещающих программное открытие календаря.

Описание работ можно вводить без справочника или сочетать с его позициями. Выбранные варианты не стирают ручной текст. Старые нестандартные работы остаются в существующих строках и доступны для редактирования. Несколько телефонов и отдельная квартира сохранены; добавлены подъезд, этаж и домофон.

Кнопки находятся в потоке формы, есть safe-area отступ, адаптация к visualViewport и прокрутка к фокусу. Заполненная форма запрашивает подтверждение при закрытии. Во время отправки кнопка показывает «Создание…», блокируется повторная отправка, сохраняется существующий request_id. Серверная ошибка оставляет черновик и выводится возле соответствующего поля, включая HTTP 409 от действующего API-слоя.

## Хранение и совместимость

| Данные | Поле | Поведение |
|---|---|---|
| Ручной номер | `orders.order_number`, nullable text | Внутренний `id`, `external_source`, `external_id` не заменяются |
| Дата поступления | `orders.received_date`, nullable date | ISO YYYY-MM-DD; не меняет `created_at` и `scheduled_date` |
| Работы | существующее `orders.work` | Ручное описание и выбранные работы, разделённые переводами строк |
| Адресные сведения | существующее `apartment`; новые `entrance`, `floor`, `intercom` | Отдельные текстовые поля |
| Неизвестная стоимость | `orders.amount_confirmed=false` | UI пишет «Стоимость не указана»/«Не рассчитано»; денежные формулы не меняются |

В действующей форме создания справочные работы сохранялись в `work`; цены каталога служили подсказками, сумма задавалась отдельно. Структурированные позиции выполненных/дополнительных работ и их расчёты не заменены описанием. Произвольному тексту не назначаются цены.

Новая миграция: `supabase/migrations/20261020140000_manual_order_intake.sql`. Она добавляет nullable-поля без заполнения старых записей, проверку и индекс ручного номера, защиту от существующих номеров в том же источнике и обновление маркера стоимости при последующем назначении ненулевой суммы. Явное очищение суммы оставляет её неизвестной.

Дубликаты ручного номера запрещены в пределах источника; Руки/Hands и Авито/Avito нормализуются как соответствующие алиасы. Один номер в разных источниках допустим. Сравнение самого номера точное, без удаления нулей. При конфликте — 409 и ошибка возле поля, без перезаписи записи.

Технические идентификаторы и архивные ключи сохранены. Имена папок/подписи запросов архивного Apps Script продолжают использовать прежний технический номер: произвольный ручной номер не может направить отчёт в чужую папку. Импортам не добавлен новый запрет по отображаемому номеру; будущая импортированная заявка может иметь отображаемый номер, совпадающий с ранее введённой ручной меткой. Уникальность технических внешних идентификаторов остаётся прежней.

При одобренном выпуске сначала требуется применить аддитивную миграцию к действующей базе, затем обновить `mini-app-api` и фронтенд. Здесь эти действия не выполнялись.

Существующие тесты прав, интеграций, выплат и расписания входят в полный набор.

UI проверен на 360, 390, 430 и 1440 px; отдельно — Tab и доступность последнего поля/кнопок при viewport 360×420. Это имитация уменьшения доступной области; физическая экранная клавиатура Android/iOS не проверялась. Тест браузерного запрета `showPicker` проверяет fallback для встроенного запуска.

## Рабочий локальный Preview

Публичный URL с отдельным тестовым backend в этой среде не предоставлен. Локальный Preview работает с реальными файлами интерфейса и действующим кодом `mini-app-api`, запускаемым через тестовый адаптер. Миграция выполняется в изолированном PGlite/Postgres; заявки сохраняются на диск, переживают перезапуск. Остальные сервисы используют вымышленные тестовые данные. Это QA-стенд, а не новая база/подключение приложения; production и облачный Supabase к нему не подключены.

Запуск после checkout ветки (Node 24):

```bash
npm ci
npm run preview:order-intake
```

Открыть `http://127.0.0.1:4175/` для владельца, `http://127.0.0.1:4175/?role=master` для назначенного тестового мастера. Для создания назначить «Мастер · тест». Внешние API-запросы в Preview запрещены, production-авторизация не используется. Тестовые записи находятся в игнорируемом каталоге `.preview-intake-data`.

Повторить автоматическую проверку и скриншоты:

```bash
npx playwright install chromium
npm run test:preview-intake
npm run test:server
npm run test:ui
npm run build:check
```

Результат `preview-verification.json`: создание → чтение после reload → SQL-конфликт дубликата → чтение мастером → перезапуск сервера → повторное чтение из сохранённого SQL-хранилища. Ошибок JavaScript страницы нет. Скриншоты получены Playwright с настоящей формой, без отрисовки макета:

- `screenshots/desktop-top.png` — начало формы, 1440×1000.
- `screenshots/desktop-work.png` — работы и дополнительные параметры.
- `screenshots/mobile-top.png` — начало формы, 390×844.
- `screenshots/mobile-bottom.png` — последнее поле, стоимость и кнопки.
- `screenshots/desktop-saved.png` — сохранённая заявка после повторного чтения.
- `screenshots/mobile-master.png` — заявка у назначенного мастера.

Полный перечень изменённых файлов: `CHANGED_FILES.txt`.
