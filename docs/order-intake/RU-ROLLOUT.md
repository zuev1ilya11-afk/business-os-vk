# Выпуск формы заявки на действующий RU-сервер

Пользователь разрешил публикацию и установку 20.10.2026. Приложение: PR #296.

Перед установкой требуется результат `scripts/ru-order-intake-check.py`, запущенного из root-консоли действующего сервера. Прямого SSH-доступа у агента нет. Скрипт выполняет только чтение: определяет активный web/edge/REST/Postgres по действующим Docker-монтированиям, проверяет целостность frontend-манифеста, выводит хеши mini-app-api и его относительных зависимостей, типы нужных полей и триггеры orders. Данные клиентов, переменные окружения и пароли не выводятся.

Скрипт не устанавливает обновление, не применяет миграцию и не перезапускает службы. Четыре локальные проверки прошли: read-only SQL, отсутствие секретов в выводе, запрет symlink/path escape, полный сценарий с подменённой границей Docker.

PR296 объединён как `27dccf2e61b64c44bfa96b97552425f04db97848` после успешного CI `39434289316`. Диагностика с сервера подтвердила build `77899953454eb1870e2e`, целостность frontend, baseline mini-app-api и три зависимости.

Установочный пакет подготовлен в `deploy/order-intake/bos296.pyz`; подробности и ограничения проверки — в `deploy/order-intake/README.md`. Целевая RU-сборка `f2c8c8ee697f23936ec2`. Пройдены 44 проверки установки/сбоев/отката, 4 сценария миграции на одноразовой PostgreSQL-совместимой базе и проверка синтаксиса 40 JavaScript-файлов пакета. Исправлено найденное ревью препятствие: недоступность БД больше не блокирует восстановление кода при откате.

Production пока не обновлён. Проверенный generic frontend нельзя просто копировать поверх серверной сборки с локальной маршрутизацией.
