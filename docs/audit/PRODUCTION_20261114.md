## Исправленная ошибка самого сборщика

Исходный скрипт из `d2f7873` проверен по SHA-256 `3a3503edce00c77c33efc2d8e2e91e5bfbe532c9d8f76f03f7039930e253dffb`. Его Docker-шаблон использовал `.Id` и прямое `.State.Health`. На HTTPS-контейнере короткий `if .State.Health` возвращал `none`, а вариант с `.Id` воспроизвёл `map has no entry for key "Health"`: Docker переключается на обработку JSON-map, где отсутствующее поле вызывает ошибку.

В `/tmp/bos-audit.py` заменён только условный доступ на `if index .State "Health"`; после этого получены успешные показатели frontend выше. Скрипт не вызывался с параметрами чтения БД. Полный JSON сохранён оператором в `/tmp/bos.json`, но аудитор пока получил только выбранные строки на скриншоте и не заявляет проверку всех его полей.

В репозитории дополнительно изолированы ошибки отдельных контейнеров: частичная ошибка сохраняет остальные результаты и явно помечает неполноту. Ошибки чтения отдельных статических файлов также сохраняют обезличенную причину и помечают неполноту; успешно прочитанное несовпадение хеша остаётся полноценным результатом диагностики. 15 Python-регрессий проходят; тест настоящего Docker CLI с синтетическим Engine API добавлен в CI. Локально два CLI-теста пропущены из-за отсутствия CLI. Полная исправленная версия сборщика с обработкой частичных ошибок на сервер пока не устанавливалась.
