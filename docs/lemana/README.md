## Поведение

- Источник `Лемана Про` добавлен в существующие поля source, формы, фильтры, карточки и финансовую группировку. `Hands` и `Руки` показываются как `Руки (Hands)` без изменения сохранённых значений. Существующая интеграция Hands остаётся включённой.
- Общая `order-payroll.js` применяет к Лемана Про прежний расчёт Hands: округление до копеек, основные работы после существующего вычета невыполненных работ, допработы отдельно. Никаких новых ставок или массового пересчёта. Финансовые снимки и проведённые выплаты сохраняются.
- Основные работы раньше хранились только текстом `work`; существующий `uncompleted_work_items` относится к вычетам. Поэтому добавлено nullable `work_items` для основных позиций: `name`, `quantity`, `unit`, `unit_price`, `amount` (сумма всей позиции). История не заполняется автоматически. При добавлении новых позиций нетронутые старые текстовые строки остаются текстом; количество и цена им не приписываются. Количество по умолчанию 1 для новых строк; штучные единицы целые; поддерживаемые меры длины/площади/времени допускают до трёх десятичных знаков и запятую.
- Общая стоимость остаётся независимым согласованным значением. Кнопка «Использовать сумму позиций» меняет её только явно. Существующие отчёты используют итоговую стоимость заказа и текст работ с количеством; повторного умножения нет.
- Импорт: выбор XLSX и часового пояса → серверная проверка → выбор новых строк → подтверждение. Предпросмотр только читает. Подписанный результат действует 20 минут и привязан к сотруднику. На подтверждении повторно проверяются права, доступность мастера и дубли. Обновления существующих заявок нет.
- Совпадение номера с другим источником блокируется как возможное совпадение; автоматического объединения и изменения источника нет. Совпадение только имени клиента не используется. Нумерация сохраняется, включая ведущие нули.
- В существующей схеме одна компания; поля tenant/company отсутствуют. Проверка охватывает её заявки, включая скрытые от сотрудника политикой города. При будущем переходе к нескольким компаниям область блокировки и поиска нужно изменить согласованно.

## Даты и ограничения импорта

В образце нет признака часового пояса. Импорт требует явного выбора IANA-зоны и показывает локальную дату и сохраняемый UTC timestamp. `created_at` — момент времени; `received_date`, `scheduled_date` и `scheduled_time` сохраняют местные календарные значения. Дата выполнения из файла остаётся метаданными и не утверждает отчёт.

Явные правила статусов находятся в `lemana-import.js`: «Подтвержден» → «Новая», «Назначена дата» → «Назначена», поддерживаемые варианты отмены → «Отменена», «В работе» → «В работе». Неизвестные требуют выбора безопасного статуса и повторной проверки. Завершение/выплаты импортом не проводятся. Мастер сопоставляется только с существующими активными сотрудниками; неоднозначность разрешается в предпросмотре.

Ограничения: `.xlsx`, 5 МиБ входного файла, 1000 строк, 256 ZIP-элементов/столбцов, 20 МиБ фактической распаковки, до 4 МиБ подписанного результата. Для слишком большого результата предлагается разделить файл. Формулы, внешние relationships, макросы и XML entities запрещены. Парсер не выполняет код и не обращается в сеть. Клиентские данные и книги не выводятся в диагностические логи.

## Рабочий предпросмотр

Открыть `preview.html` в браузере. Это исходные CSS/JS текущего приложения, собранные в один автономный HTML. Верхняя панель открывает форму и импорт, скачивает синтетический XLSX с новой строкой, существующей строкой, совпадением ручного номера и ошибкой статуса.

Применяются реальные обработчики API, общие правила разбора и расчёта; хранилище демонстрации находится только в памяти браузера, SQL RPC заменён локальным create-only адаптером. Перезагрузка сбрасывает изменения. CSP запрещает внешние соединения. Реальный SQL отдельно проверяется PGlite и двумя сессиями PostgreSQL в CI. Не загружайте в демонстрацию реальные клиентские отчёты.

Воспроизведение:

```sh
npm ci
node scripts/build-lemana-xlsx.cjs
npm run build
node scripts/build-lemana-preview.cjs
node scripts/verify-lemana-preview.cjs
npm run test:server
npm run build:check
```

Полный UI-набор запускается в CI через `scripts/test-ui-offline.sh`: отдельный network namespace без внешней сети. Проверка `gas-bridge-health` требует отдельной авторизации на онлайн-проверку и в этом режиме пропускается.

## Миграции

Предпосылка из актуального main: `20261020140000_manual_order_intake.sql` (номер и дата поступления, без её повторного применения, если уже установлена).

Новая миграция: `20261020180000_lemana_import_work_items.sql`:

1. Nullable `orders.work_items`, `orders.lemana_import_meta`; ограничение формы массива.
2. Функция извлечения существующих бизнес-номеров.
3. BEFORE trigger с advisory locks и привилегированной проверкой дубля через городские RLS-границы. Остальные источники сохраняют прежние правила.
4. Create-only RPC `bos_import_lemana_order`. Вызов доступен только `service_role`, сотрудник проверяется повторно внутри транзакции.

Миграция не содержит UPDATE исторических заказов и начислений. Публичные/пользовательские права на импортный RPC не выдаются.
