# Google Apps Script backend

## Обновление после исправления подписи VK

Изменение `Code.gs` в GitHub не обновляет опубликованный Google Apps Script.

1. Откройте существующий проект Apps Script, обслуживающий URL из `config.js`.
2. Полностью замените содержимое `Code.gs` файлом из этой папки и сохраните.
3. В Project Settings → Script Properties должен быть `VK_APP_SECRET` — защищённый ключ именно приложения **54758847**. Значение хранится только там: не вставляйте его в код, GitHub, frontend или сообщения.
4. Откройте Deploy → Manage deployments, выберите текущее Web app и нажмите Edit (карандаш).
5. В Version выберите New version и нажмите Deploy. Сохраните Execute as: Me и Who has access: Anyone.
6. При обновлении существующего deployment его URL остаётся прежним: `config.js` менять не требуется. Закройте Mini App и откройте заново внутри VK.

Простое сохранение кода без публикации новой версии оставляет `/exec` на старой версии. См. [инструкцию Google](https://developers.google.com/apps-script/concepts/deployments#edit_a_versioned_deployment).

## Как проверяется подпись

Frontend один раз сохраняет `window.location.search` без начального `?`, до асинхронных вызовов bridge. Он передаёт всю исходную строку как значение `launch_params` через `URLSearchParams`: без предварительного `decodeURIComponent` или `encodeURIComponent` и без восстановления параметров из данных профиля.

Apps Script получает уже декодированное внешнее значение в `e.parameter.launch_params`. Затем разбирает внутреннюю строку по `&` и первому `=`, декодирует каждый ключ и значение один раз (`+` означает пробел). Повторяющиеся подписанные ключи и повреждённая кодировка отклоняются.

Для HMAC выбираются только ключи с префиксом `vk_`, сортируются по возрастанию и сериализуются как `URLSearchParams`: пробел → `+`, буквальный плюс → `%2B`, специальные символы кодируются, пустые значения сохраняются. `sign` и параметры интерфейса не включаются. `formEncode_` реализует эту сериализацию без браузерного API в Apps Script.

Подпись — HMAC-SHA256 от UTF-8 строки с `VK_APP_SECRET`, затем base64url без `=`. Дополнительно проверяются ID приложения и наличие ID пользователя; ошибка подписи останавливает запрос до обращения к таблице.

Источники: [передача параметров VKCOM](https://github.com/VKCOM/vk-apps-launch-params#передача-параметров-запуска-на-сервер), [официальный пример проверки и тестовый вектор](https://github.com/VKCOM/vk-apps-launch-params/blob/master/examples/python3.py).

## Проверки

Из корня репозитория (Node.js 18+):

```sh
node --test tests/vk-signature.test.cjs
```

Тесты выполняют реальный `Code.gs` с заменой сервисов Google и реальный frontend с заменой DOM/bridge. Проверяются native URLSearchParams + Node crypto, опубликованный пример VKCOM, положительные и отрицательные случаи и сохранение launch params при изменении URL. Используются только искусственный тестовый ключ и публичный ключ из примера VKCOM — не секрет приложения Business OS. Настоящие Google-сервисы и вход VK эти локальные тесты не проверяют.
